# 帕斯卡画廊网站信息架构与二级页面设计

## 目标

让项目客户、艺术品客户、艺术家及合作机构、潜在投资人都能快速理解帕斯卡画廊可以提供什么服务，并通过清晰入口进入适合自己的详细内容。

网站采用“统一定位 + 四类需求入口 + 五项服务能力 + 案例证明”的叙事结构。首页负责说明与分流，二级页面负责详细介绍和建立信任。

## 公开内容边界

- GitHub Pages 只展示可公开的机构、服务、案例、作品和发展信息。
- 投资人可以从官网了解资源积累、业务结构、项目能力和发展潜力。
- 融资金额、估值、股权、资金用途、财务预测和投资条款只进入融资 PPT，不进入公开网站。
- 未确认授权的客户名称、项目图片、艺术家资料和第三方材料不公开。

## 统一定位

首页核心表达：

> 帕斯卡画廊以艺术家与作品资源为基础，为个人、企业、商业空间和城市项目提供艺术品交易、内容策划、空间设计及公共艺术制作落地服务。

这句话同时覆盖画廊的资源基础、主要客户、五类业务和完整交付能力，避免将帕斯卡表达成单纯销售艺术品的机构。

## 首页信息顺序

### 1. 首屏定位

- 标题：帕斯卡画廊
- 核心定位：综合艺术服务机构
- 一句话说明：使用上述统一定位文案
- 主要按钮：了解服务
- 次要按钮：浏览在售作品

### 2. 四类需求入口

访客按自身需求进入相关内容：

1. 我要购买或租赁艺术品
2. 我要做空间、商业或文旅项目
3. 我要寻求艺术家或机构合作
4. 我要了解帕斯卡的发展与能力

每个入口显示一句结果导向的说明，并链接到对应服务、作品、案例或机构页面。

### 3. 五项服务能力

首页保留五张服务卡，但内容控制为“服务名称 + 适合对象 + 解决的问题 + 查看详情”。整张卡可点击进入相应服务二级页。

五项服务保持用户确定的分类：

1. 艺术品销售
2. 艺术品与场地租赁
3. 文旅项目策划
4. 设计
5. 景观艺术品制作施工

### 4. 完整工作链

用五个连续阶段说明帕斯卡如何交付：

> 需求诊断 → 艺术资源组织 → 策划与设计 → 制作与施工 → 展示与运营

每个阶段用一行短说明解释工作边界。该部分重点证明帕斯卡不仅提供创意，也能把项目落地。

### 5. 场景解决方案

按客户容易识别的场景组织入口：

- 酒店与商业空间
- 文旅目的地与城市活动
- 街区、园区与公共空间
- 企业收藏与艺术配置
- 展览、品牌活动与临时场地

场景入口链接到已筛选的案例目录或相关服务页。

### 6. 代表案例

首页只展示少量代表案例。每项写清：

- 客户或场景面临的问题
- 帕斯卡完成的主要工作
- 最终交付成果
- 可公开的项目结果

案例卡进入案例详情页；缺少授权图片时使用清楚的文字内容和统一封面，不虚构图片或项目结果。

### 7. 机构实力与发展潜力

公开展示运营起点、累计展览、合作艺术家、学术活动、服务链条和项目场景。面向投资人的表达聚焦：

- 艺术家、作品和内容资源可以持续积累
- 服务模块可以跨商业、酒店、文旅和公共空间复用
- 收入来源覆盖销售、租赁、策划设计和制作施工
- 画廊运营为项目业务提供长期资源基础

该部分不出现融资数据和投资条款。

### 8. 合作入口

提供四个明确动作：

- 浏览在售作品
- 提交项目需求
- 艺术家与机构合作
- 了解帕斯卡

## 二级页面结构

### 服务二级页

建立五个可分享的静态路径：

- `services/art-sales.html`
- `services/art-space-rental.html`
- `services/cultural-tourism.html`
- `services/design.html`
- `services/landscape-art.html`

五个页面使用相同内容模板：

1. 服务名称和一句结果导向的定义
2. 适合哪些客户和场景
3. 可以解决哪些问题
4. 帕斯卡具体负责哪些工作
5. 标准工作流程
6. 可以交付哪些成果
7. 相关代表案例
8. 关联服务和下一步合作入口

页面内容从统一服务数据读取；每个 HTML 页面通过固定服务编号选择内容，避免五份内容结构分别维护。

### 案例页面

- `cases.html`：案例总目录，支持按服务类型、项目场景和年份浏览。
- `case.html?id=<案例编号>`：统一案例详情模板。

案例详情统一回答：

1. 项目背景与适用场景
2. 核心问题
3. 帕斯卡承担的工作
4. 实施过程
5. 可交付成果
6. 可公开的项目结果
7. 相关服务

缺少、无效或未公开的案例编号显示中文提示，并提供返回案例目录的入口。

### 在售作品

- `works.html`：推荐作品和详细目录。
- 第一阶段继续使用统一目录，不立即新增单件作品页面。
- 已确认的“搜索 + 艺术品种类 / 艺术家双分类”按独立实施计划完成。
- 后续真实作品资料完整时，再增加 `work.html?id=<作品编号>`。

### 关于帕斯卡

- `about.html`：机构介绍、发展历程、2023-2025 年度事件、2025 年空间装修升级、数据成绩、资源基础和公开发展方向。
- “机构发展”先作为 `about.html` 内的独立板块，不立即建立单独页面。
- 融资 PPT 可以引用公开事实，但官网不读取或链接融资文件。

## 页面导航

主导航统一为：

1. 首页
2. 服务
3. 案例
4. 在售作品
5. 关于帕斯卡
6. 合作

“服务”在桌面端可展示五项服务入口，在移动端进入服务总览区域或服务页面列表。所有二级页面保留返回上一级的清楚入口。

## 内容与数据组织

- `data/xu-services.json` 继续保存服务与案例公开数据，并补充二级页需要的适用对象、问题、流程和交付成果字段。
- 首页、服务页和案例页读取同一份公开数据，避免同一段事实在多个文件中重复维护。
- `data/works-for-sale.json` 继续独立维护在售作品，不与项目服务数据混合。
- 机构历程使用独立公开数据文件维护，便于后续按年度增加内容。
- 页面只读取明确标记为可公开的内容。

## 视觉和交互原则

- 延续白色背景与鲜绿色点缀。
- 首页保持简洁，服务和案例详情页可以承载较长内容。
- 可点击卡片必须有明显的标题、简短说明和“查看详情”提示。
- 不使用大量悬浮卡片或复杂动画；重点保持中文内容清楚、易扫读。
- 桌面端和移动端不得出现文字截断、控件重叠或横向滚动。

## 异常与空内容

- 数据加载失败时显示中文错误提示和返回首页入口。
- 没有授权图片时使用统一占位封面，不显示失效图片。
- 没有相关案例时显示“相关案例正在整理”，但服务页的工作内容、流程和交付信息仍需完整展示。
- 不展示空标题、空列表或“待补充”字段给公开访客。

## 分阶段实施

### 第一阶段：服务表达

- 重写首页定位与内容顺序
- 增加四类需求入口
- 建立五个服务二级页
- 建立统一服务页数据与导航

### 第二阶段：案例与机构

- 建立案例总目录和案例详情模板
- 建立关于帕斯卡页面
- 将已有年度总结整理为公开时间线

### 第三阶段：作品目录

- 执行已确认的在售作品搜索与双分类计划
- 真实作品资料完整后评估单件作品详情页

每个阶段均应独立完成自动化检查、桌面和移动端浏览器验证，并在上线后确认 GitHub Pages 返回 HTTP 200。

## 验收标准

- 新访客在首页首屏可以准确复述帕斯卡是什么机构。
- 四类受众都能在首页两次点击以内到达相关内容。
- 五项服务都有可分享的二级页面，并清楚回答适合谁、解决什么、做什么和交付什么。
- 案例与服务建立双向关联，不再只是无上下文的项目列表。
- 公开机构发展内容可以帮助投资人理解业务价值，但不包含任何融资敏感信息。
- 所有新增页面和交互文字为中文。
- 所有页面在桌面和手机端可正常阅读，无横向溢出。
