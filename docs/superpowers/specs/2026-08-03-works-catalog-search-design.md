# 在售作品目录搜索与双分类设计

## 目标

在现有“详细目录”中增加搜索功能，并允许访问者在“艺术品种类”和“艺术家”两种分类方式之间切换。功能继续使用静态 GitHub Pages，不引入后端或融资内容。

## 页面布局

- 目录工具栏左侧放置“艺术品种类 / 艺术家”分段切换控件。
- 当前模式对应的分类按钮显示在工具栏下方，并保留“全部”选项和每项数量。
- 搜索框位于工具栏右侧，输入提示为“搜索艺术家、作品名或编号”。
- 桌面端保持左右布局；窄屏下搜索框换到下一行并占满可用宽度。
- 继续使用现有白色背景、黑色文字和鲜绿色交互点缀，不改变目录表格结构。

## 交互规则

1. 页面初始模式为“艺术品种类”，初始分类为“全部”，搜索词为空。
2. 切换分类模式后，分类按钮立即更新：
   - 艺术品种类模式读取现有 `categories` 配置。
   - 艺术家模式从作品的 `artist` 字段生成去重列表，并显示作品数量。
3. 切换模式时分类重置为“全部”，搜索词保留。
4. 分类与搜索条件同时生效。
5. 搜索忽略大小写与首尾空格，匹配编号、艺术家、作品名、年份、媒介、种类、价格、状态和备注。
6. 分类按钮上的数量表示该分类的总作品数，不随当前搜索词变化，避免按钮数量在输入时跳动。
7. 没有匹配结果时显示“没有找到符合条件的作品，请调整分类或搜索词。”
8. 清空搜索框后立即恢复当前分类下的全部作品。

## 实现边界

- 在 `works.html` 中增加模式切换与搜索输入控件。
- 在 `works.js` 中维护模式、当前分类和搜索词三项页面状态，并由同一个筛选函数计算可见作品。
- 艺术家分类直接从现有 JSON 生成，不新增或重复维护艺术家列表。
- 在 `styles.css` 中增加工具栏、分段控件、搜索框及移动端样式。
- 不改变 `data/works-for-sale.json` 的字段结构，不增加后台、登录、价格计算或融资内容。

## 可访问性与异常处理

- 模式切换使用按钮和 `aria-pressed` 表达当前状态。
- 搜索输入具备可见标签或无障碍标签，并使用原生清除能力。
- 分类按钮继续使用 `aria-pressed`。
- 数据加载失败沿用现有中文错误提示；筛选无结果使用单独的中文空状态。

## 验收标准

- 两种分类模式都能正确生成按钮及数量。
- 分类和搜索可组合使用，结果正确且清空搜索后恢复。
- 搜索可匹配艺术家、作品名、编号和媒介等字段。
- 桌面端搜索框位于工具栏右侧；手机端无横向溢出。
- 所有新增界面文字为中文。
- 本地自动化测试、浏览器交互检查和 GitHub Pages 在线访问均通过。
