# 作品图片录入与管理页设计

## 目标

从用户提供的三份 PPT 中识别、提取并去重作品图片，建立可持续维护的作品数据；新增独立中文管理页，让画廊能够新增、编辑、推荐、上架、下架、删除、导入和导出作品，并将确认后的修改直接提交到 GitHub。公开 GitHub Pages 只展示已上架作品，不展示管理凭据或内部备注。

## 内容录入

- 读取《帕斯卡画廊商业宣传》《罗浮宫 艺术、展览、活动策划 概念框架方案（1）》《柏典tianjin》三份 PPT。
- 从幻灯片关系中定位图片及所在页码，剔除标志、图标、背景、装饰纹理、重复图片和明显的项目环境参考图。
- 无法可靠确认作者、作品名、年份、媒介、尺寸和价格时，不猜测；使用“待补充”，并将记录状态设为“待整理”。
- 每条记录保留来源文件、页码和原始图片文件名，内部可查但不在公开页显示。
- 新录入内容默认不公开；只有在管理页明确改为“已上架”后才进入公开在售作品页。

## 数据结构

统一使用 `data/works-for-sale.json` 作为作品数据源。每条作品包含编号、艺术家、作品名、年份、媒介、尺寸、分类、价格、销售状态、公开状态、推荐状态、作品说明、推荐理由、图片路径、内部备注和来源信息。公开页读取同一份数据，但只渲染 `publishStatus: "published"` 的记录。

作品图片存放在 `assets/works/<作品编号>/`。管理页上传新图片时，先校验图片类型和大小，再写入该目录并更新 JSON。

## 管理页

新增不出现在公开导航中的 `admin/works.html`：

- 顶部提供 GitHub 精细权限令牌输入和连接状态。令牌只保存在内存或 `sessionStorage`，关闭标签页后失效，不进入仓库、日志或导出数据。
- 左侧为作品列表，可按编号、艺术家、作品名、分类和状态搜索筛选。
- 右侧为编辑表单，支持新增、修改、图片预览与替换、推荐开关、上架与下架。
- 删除采用二次确认；默认优先“下架”，避免误删历史记录。
- 支持导入标准 JSON 和导出当前完整作品 JSON，便于备份与批量整理。
- 保存时通过 GitHub API 获取目标分支最新 SHA，提交图片和数据文件；若远端已变化则停止覆盖并提示刷新，避免冲突。

## GitHub 授权

采用用户本人创建的 GitHub fine-grained personal access token，只授予 `sibolees-jpg/pascal--gallery` 仓库的 Contents 读写权限。管理页不内置任何密码或令牌。没有令牌时页面仍可离线编辑和导出，但不能提交到 GitHub。

## 公开页面

- 保留“推荐板块 + 详细目录板块”。
- 只显示已上架作品；推荐板块只显示已上架且已推荐的作品。
- 保留艺术品种类、艺术家两种分类方式和搜索。
- 图片与信息不完整时显示明确中文状态，不伪造信息。

## 异常与安全

- 拒绝非 JSON 导入、非法字段、重复编号、超限图片和不支持的图片格式。
- 所有用户输入在渲染前转义，避免脚本注入。
- GitHub API 的 401、403、409、422 和网络错误均显示可执行的中文提示。
- 不在公开页面暴露来源文件路径、内部备注、令牌或 GitHub API 响应细节。

## 测试与验收

- 数据校验、筛选、公开状态、推荐状态、导入导出和 GitHub 提交载荷使用无 DOM 单元测试。
- 管理页测试新增、编辑、下架、删除确认、图片选择、错误提示和窄屏布局。
- 公开页测试只展示已上架作品，分类与搜索组合有效。
- 检查所有提取图片可加载、没有重复文件、记录包含来源页码。
- 发布前运行全部自动化测试、语法检查、桌面与手机浏览器检查，并确认 GitHub Pages 构建成功。
