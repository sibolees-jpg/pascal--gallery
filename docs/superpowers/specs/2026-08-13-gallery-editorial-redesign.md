# 帕斯卡画廊前台视觉改版设计

## 目标

将现有网站从偏企业服务介绍的视觉，调整为“当代画廊 + 艺术档案 + 综合艺术服务”的统一形象。网站仍需让客户快速理解帕斯卡能做什么，但第一感受应首先是专业画廊，而不是咨询公司。

## 设计原则

1. 白色背景、黑色文字、鲜绿点缀保持不变。
2. 真实展览、作品和项目图片承担主要视觉表达，图片保持原比例完整显示。
3. 减少圆角卡片、胶囊按钮和成片浅灰底，改用留白、细分隔线、文字层级和编辑式网格。
4. 鲜绿仅用于当前状态、关键链接、筛选结果和主要行动，不作为大面积背景。
5. 中文为主；艺术家、展览或品牌的原名可以保留。

## 参考方式

- Meyer Riegger：学习强字标、密度变化和非均质图片网格，不照搬夸张比例。
- Galerie Lauffer：学习留白和安静节奏，但不牺牲信息效率。
- Luis Leu：学习日期、人物、地点与大图直接组合的展览详情结构。
- White Cube：学习艺术家、展览、新闻和档案的清晰分类及筛选方式。
- UBS Art：学习专题文章中的标题、导语、作品大图、图注与正文节奏。

## 页面结构

### 全站导航

- 标志保持完整，不改品牌图形。
- 导航固定为：首页、展览与动态、艺术家与作品、案例、关于、合作。
- “服务”不再作为最强视觉入口，而是在首页和案例中清楚呈现。
- 桌面端保持一行；手机端使用紧凑换行，不引入复杂抽屉菜单。

### 首页

1. 首屏使用真实展览现场作为完整背景，保留“帕斯卡画廊”中文名称与城市文化基础设施定位。
2. 首屏之后首先出现“正在发生 / 最新内容”编辑式网格，混合展览、作品与案例，图片尺寸有层级差异。
3. 将“艺术 × 商业 × 消费 × 服务”压缩成一条方法说明，不再使用四张大卡片。
4. 五项服务改为文字目录，每项包含一句能力说明和真实案例数量。
5. 机构数据、专业网络和发展历程作为次级内容，链接到关于页面。
6. 删除重复的适用场景、案例分类矩阵和发展卡片，避免同一信息多次出现。

### 案例目录

- 采用 White Cube 式档案逻辑：顶部标题，下面是服务类型筛选和关键词搜索。
- 案例列表使用图片主导的编辑式网格，而不是横向企业案例卡片。
- 每张内容只显示项目名称、年份、地点和类型，摘要在详情页阅读。
- 图片完整显示，并允许横图、竖图采用不同网格跨度。

### 案例详情

- 第一屏采用项目名称、年份、地点、类型与代表图组合。
- 正文依次为项目背景、核心问题、帕斯卡工作、过程、成果、交付物。
- 图片按原比例穿插在正文中，每张图片必须有中文图注。
- 长正文宽度受控，避免整页大字号或企业报告式成组卡片。

### 在售作品

- 保留现有搜索、艺术品种类和艺术家双分类。
- 推荐区改为更开放的作品墙；目录使用紧凑、可扫描的档案列表。
- 作品图片继续 `object-fit: contain`，不裁切。
- 后台管理页面不参与此次视觉改版，以免影响作品提交功能。

### 关于页面

- 保留机构历史、创始人、专业网络和时间线。
- 增加留白，减少边框盒子；展览现场图片以大幅横图呈现。
- 历史信息采用年份与事件并列的档案排版。

## 数据与技术边界

- 不改变 `data/works.json`、`data/cases.json`、`data/xu-services.json` 的既有字段契约。
- 首页内容继续从现有公开数据生成，不复制一套静态案例内容。
- 新增前台展示逻辑时保持无框架静态页面，兼容 GitHub Pages。
- 管理端、GitHub 令牌和作品提交逻辑不改。

## 响应式与可访问性

- 桌面重点验证 1440px，手机重点验证 390px。
- 页面不得横向溢出；标题先换行，不缩到无法阅读。
- 图片必须有替代文字；筛选控件保留键盘焦点和当前状态。
- 动效仅使用轻微淡入或悬停变化，并尊重减少动态偏好。

## 验收标准

1. 首页第一屏清楚呈现画廊身份和真实展览现场。
2. 首页重复模块减少，首屏后能直接看到最新内容。
3. 案例目录具有筛选、搜索和图片主导的档案感。
4. 案例与作品图片均完整显示，不出现半截画面。
5. 桌面与手机端无横向溢出。
6. 既有管理端和公开作品筛选测试全部通过。
7. GitHub Pages 正式网址可访问新版本。
